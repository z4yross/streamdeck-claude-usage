# Contributing

Issues and pull requests are welcome. Keep changes small and focused; one topic per PR.

## Prerequisites

- Windows 10 or later (the plugin is Windows-only)
- Node.js 20
- Stream Deck software 6.9 or later and a Stream Deck+ (the action is dial-only)
- Claude Code installed and logged in, so there is a `.credentials.json` to read

## Set up

```bash
git clone https://github.com/z4yross/streamdeck-claude-usage.git
cd streamdeck-claude-usage
npm install
npx streamdeck link com.z4yross.claudeusage.sdPlugin   # symlinks the plugin into Stream Deck
npm run watch                                          # rebuilds and restarts the plugin on save
```

`streamdeck link` creates a junction in `%APPDATA%\Elgato\StreamDeck\Plugins`, so the
Stream Deck app runs straight from your working copy. If you already installed the
Marketplace build, uninstall it first; both use the same UUID.

## Project layout

| Path | What |
| --- | --- |
| `src/plugin.ts` | Entry point: registers the action and connects |
| `src/actions/dial.ts` | The dial: state per dial, polling, gestures, painting |
| `src/usage-api.ts` | Reads the OAuth token of a config dir and calls the usage endpoint |
| `src/predict.ts` | Pace tracking and extrapolation |
| `src/icons.ts` | Colours and the account badge |
| `com.z4yross.claudeusage.sdPlugin/` | What ships: manifest, layout, property inspector, images, built `bin/` |
| `marketplace/` | Listing assets and copy for the Elgato Marketplace |

`bin/plugin.js` is generated by Rollup and ignored by git.

## Debugging

- Logs: `com.z4yross.claudeusage.sdPlugin/logs/`. The level is set to `debug` in `plugin.ts`.
- Node inspector: the manifest starts Node with `--inspect=127.0.0.1:12348`. Attach from
  VS Code or `chrome://inspect`.
- Add accounts in the property inspector as `Label=config dir` pairs to test several
  tokens, for example `Personal=~/.claude,Work=~/.claude-work`.

Never commit tokens, `.credentials.json` contents or log files. Logs print usage
percentages only, but check before pasting them into an issue.

## Checks

The same checks CI runs:

```bash
npm run build
npx streamdeck validate com.z4yross.claudeusage.sdPlugin
npx streamdeck pack com.z4yross.claudeusage.sdPlugin -o dist
```

## Conventions

- TypeScript, tabs, double quotes, as in the existing files.
- Conventional commits, single line: `type(scope): subject`, lowercase, imperative,
  no trailing period. Examples: `fix(dial): keep last good numbers on 429`,
  `feat: show opus window`.
- Everything in the repo is in English: code, comments, docs, commit messages.
- Do not change the plugin or action UUIDs; the Marketplace ties the product to them.
- Keep the touch-strip layout inside 200×100 and under 10 updates per second (Elgato
  guideline).

## Pull requests

1. Fork and branch from `main`.
2. Make the change, run the checks above, test it on a real Stream Deck+.
3. Open a PR describing what changed and why, with a screenshot or a short description
   of what the dial shows when the change is visible.

CI builds, validates and packs every PR; the `.streamDeckPlugin` is attached to the run
as an artifact if you want to try the exact build.

## Releasing (maintainers)

1. Bump `Version` in `com.z4yross.claudeusage.sdPlugin/manifest.json` (four parts,
   for example `0.3.0.0`).
2. Commit, then tag and push:

   ```bash
   git tag v0.3.0
   git push origin main v0.3.0
   ```

   CI checks the tag against the manifest version, packs the plugin and attaches it to the
   GitHub release.
3. Upload that `.streamDeckPlugin` in Maker Console under **Versions > Create version**.
   The Marketplace has no API; this step is manual.
